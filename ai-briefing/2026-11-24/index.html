官方确认智谱发布旗舰模型 GLM-5.4：Loop Transformer，对标「泛 Coding」

11/23 17:42（北京时间），智谱官方公众号发布《GLM-5.4：瞄向泛Coding，首个Loop Transformer带来的惊喜》；Z.ai 同步刊出技术博文，X 账号 @Zai_org 于 18:27 转发。公司称这是把已预训练的 GLM-5 基座改造成 Loop Transformer 的第一代旗舰：对其中 28 层做两轮权重共享循环，参数规模写为 750B，并自称智能水平可达到 2T–3T 级模型的效果。官方说明，循环不是从零预训练，而是在已有基座上继续训练，以较小算力开销提高有效深度；并介绍了门控渐进更新、跨循环 KV 共享加滑动窗口、稀疏注意力索引复用等部署改动。推断速度自称闲时最高约 200 tokens/s、高峰约 70–80 tokens/s。

可用性上：即日起向 GLM Coding Plan 全量用户开放，并写明同步上线 ZCode、Trae、WorkBuddy、Qoder 等编码平台；API「将在完成安全评估后开放」，权重「计划以负责任的方式开源」。博文自己列出主要局限：模型容易陷入过长的「马拉松式思考」，尽管这种反复自纠会提高准确率。本条已在 11/23 17:56 的小时大事提醒中告知，早报按截止规则收入，不当作新的首次发现。

官方确认Anthropic 推出 Claude Ship 测试版：审查、修复并按策略审批 PR

11/23，Anthropic 官方文章宣布 Claude Ship 即日起以测试版上线。它由已经正式提供的 Code Review，以及两个测试版智能体 PR Steward、Claude Approvals 组成。Code Review 可按 Quick / Standard / Deep 对拉取请求做多角度检查并回帖；PR Steward 负责失败的 CI、合并冲突和评审意见，设计上「不批准、不合并」，每次推送后说明改了什么以及如何撤销；Claude Approvals 读取仓库里的策略文件，对策略允许的常规变更可以自行批准，高风险变更仍要求人审，官方建议先用观察模式，再考虑把它纳入分支保护。

开发者可在 Claude Code 里用 /ship 对单个 PR 走完流程；管理员也可以按仓库打开自动流转。可用范围是 Claude Team 与 Enterprise、且仓库在 GitHub 上。按 token 计费，管理员可为 Code Review 和 PR Steward 设置支出上限；Zero Data Retention、HIPAA 配置和客户管理密钥的组织不可用。合格 Enterprise 客户可在 2027-01-15 前领取至少 1 万美元、须在领取后 30 天内用完的额度，条款另计。TechCrunch 稿件时间为 11/23 14:05 PST（北京时间 11/24 06:05，仍在截止前）。

官方确认OpenAI 与思科开源 Shirudo：用 eBPF 为运行中的 Linux 系统加临时防护

11/23，OpenAI 发布官方文章，宣布与思科推出开源 Linux 运行时 Shirudo（日语「盾」）。目标是在补丁测试和滚动部署仍需数日乃至数周时，先加载经过操作员批准的 eBPF「盾」，挡住暴露漏洞的行为，同时尽量放行合法请求，而不必为了防护而重启服务。官方列举四项能力：在线防护、给防御方智能体的可编程控制（部署仍由安全团队决定）、盾的签名与 eBPF 验证器检查，以及用 TPM 留下可核验的加载/卸载记录。文章举了一个受控实验：用 Codex 生成的盾，在无需重启的情况下挡住了对运行中 Elasticsearch 的 Java4Shell 利用尝试。许可证为 BSD 2-Clause，BPF 程序双许可 BSD 与 GPL。Greg Brockman 在文中和 X 上转述了同一发布。

同日较晚，OpenAI 官号又介绍 GPT-6 Cyber 在一次运行中帮助验证 948 个可本地提权的 Linux 内核漏洞并生成供审查的补丁。但这篇研究报告页面标注日期为 2026-11-04，正文写的是「即将推出的网络模型」流水线，不能当作本窗新发表的论文；只作为与 Shirudo 同一防御主题的既有研究被再次传播，不单列为新头条。

黄仁勋复职被当成供应链信心信号，而非调查结束。 Sam Altman 发了一句 “Jensen!”；英伟达研究者 Jim Fan 和 Hugging Face 的 Clement Delangue 把复职读成「回来干活 / Jensen 2.0」。这是公开站台和情绪，证明的是这些人当时怎么表态，不能当成市场共识，更不能当成独立董事调查已经收尾。

编码工作流的下一步：审查与合并，而不只是写代码。 Claude Ship 把评审、修 CI 和按策略审批写进同一产品；GLM-5.4 则把「泛 Coding」和 Loop 架构当作自己的主叙事。一个常见判断是：当模型已经能写大量代码，瓶颈会移到评审和合并纪律。分歧在范围和证据：Ship 目前限于 Team/Enterprise 与 GitHub，官方还建议审批先走观察模式；GLM 的能力对照和速度数字仍是厂商自报，API 与权重都还没开放。

不要把当日其他高声量讨论写成新事实。 Yann LeCun 继续在回复里争论 LLM 的错误是否可恢复，这是他一贯立场的延续，不是新的产品或论文发布。Perplexity 的 Aravind Srinivas 强调用户在切到 Gemini 4 Neon，并称尚未默认路由——这是商家自己的流量叙述。OpenAI 研究旧文在官号再次传播，也不等于 11/4 的报告重新发表。

正反辨析

复职以董事会一致决议和政府意见入文，市场给出了可核对的价格。 新闻稿、8-K 和收盘数据是清楚的：职务即刻恢复，调查委员会、出口管制委员会和合规官招聘被一并写下，说明公司至少在治理形式上没有宣布「翻篇」。
调查未结束，总统「说服董事会」也不能写成法定程序。 「不构成国家安全风险」来自董事会对政府意见的转述，不是调查报告的结论。单日市值回升很大，但相对近期高点仍有缺口；把反弹写成风险出清，会超出已公开的事实。
Agent 开始进入「谁有权合并」这一层，而不是只生成补丁。 Claude Ship 把审批写成仓库里的策略文件，并明确建议先观察再接入分支保护；Shirudo 则把「盾」的部署权留在操作员手里。这两条都比「模型会写代码」更接近真实生产约束。
可用范围和计费会迅速限制谁真的能打开这些开关。 Ship 排除 ZDR/HIPAA/CMEK，并按 token 计费；GLM-5.4 的 API 与权重仍待安全评估。内部评审指标和厂商基准，都不能直接当成你这边仓库或任务的预期收益。
